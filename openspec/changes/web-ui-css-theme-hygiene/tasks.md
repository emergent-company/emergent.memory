## 5. Stylesheet consolidation — partially delivered; remainder deferred to a follow-up unit

Delivered in this change: 5.3 (colour tokens) and 5.4 (the FOUC guard, folded into §4).

Deferred: 5.1 (injected-sheet subset), 5.2 (muted-text/icon scale), 5.5 (page-local `<style>` blocks) and
5.6 (hand-rolled classes). Measurement showed this group is neither small nor appearance-neutral — see the
proposal's fourth-unit note. The `web-ui-css` injected-stylesheet requirement was removed from this change's
delta, so nothing here is left unmet by the PR. The measurements below are retained so the follow-up unit
starts from facts rather than from the audit's estimates.

- [ ] 5.1 Reduce the JS-injected duplicate rules in `webui/static/js/chat-components.js` to a documented, tested subset. **Scope measured — it is larger and subtler than it first looked:** the injected sheet references 84 selectors, and **47 of them are also defined in `app.css`** (`.memory-queue-*`, `.memory-copy-btn*`, `.memory-rail-badge*`, `.memory-run-marker*`, `.memory-turn-footer*`, `.dock-*`, `.memory-code-wrap*`, `.memory-queue-row`, …). Extract with a script that gathers `"sel{"` from the JS and greps `app.css` for the same selector.

  **Why it cannot be a blind deletion:** the injected sheet is appended to `<head>` *after* the compiled Tailwind sheet, so at equal specificity it wins and several rules exist precisely to override `app.css` (the source carries a comment about exactly this, on `.memory-rail-badge`). A duplicate is therefore either (a) an intentional override that must stay and be documented, or (b) accidental duplication that should go. Each of the 47 needs its rule *body* diffed against `app.css` and classified before anything is removed.

  **Required approach:** classify all 47 (override vs duplication), delete only the (b) cases, keep the (a) cases with a comment saying why the injection wins, and add the automated sync check the requirement calls for so the two sources cannot drift further. Removing a (a) case silently changes chat rendering. Also keep the badge rules that the active `error-contrast-remediation` change requires to stay in sync with `app.css`.

  **Do not attempt this as part of a larger sweep.** It is a self-contained diff-and-classify task on one file plus one sheet.
- [ ] 5.2 **Deferred to its own unit** — the muted-text and icon-size scale. Introducing a scale that 12 opacities and a drifting icon-size spread must all move to is a ~500-site sweep across essentially every template, and the requirement says *no* opacity outside the scale, so a partial migration would leave the requirement unsatisfied. It has been moved out of this change (the requirement was removed from `web-ui-css` and is recorded in the proposal) so this unit can land without silently dropping it. The scale's definition and the migration belong together in that follow-up unit.
- [x] 5.3 Token-ize the remaining hardcoded colours: `.memory-md pre` background → `var(--color-base-200)`, `.chat-bubble.chat-bubble-neutral` background → `var(--color-base-100)`, and the shimmer's `#fff` stop → `oklch(1 0 0)` (no theme token exists for "brighter than base-content", so it is kept as a documented decorative literal). - [x] 5.4 De-triplicate the inline FOUC `<style>` guard into one shared component (done as part of §4: `foucBackgroundGuard()`, one literal, three call sites).
- [ ] 5.5 Move the page-local `<style>` blocks that duplicate shared idioms into the shared stylesheet. **Measured scope:** `<style>` appears in 4 template files — `ui.templ` (the app shell), `chat.templ`, `auth_ui.templ`, `share_page.templ` — versus the 3 the audit listed.
