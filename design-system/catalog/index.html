Design system · v1

One token source. Everything else generated.

Memory's foundations and identity in one place, rendered from the artefacts the product actually ships — not a mock-up of them. The colours below are the shipped CSS custom properties, the mark is the shipped SVG geometry, and the contrast table is the same computation the build gate runs.

Values live here; component anatomy lives in go-daisy and UI patterns live in the ui-patterns graph pack. This page federates the three — it owns none of them twice.

Identity

The mark

A brass tile with an M. The letter is a path, not live text: the shipped monogram set the M in the system font, so its shape changed with the font stack, could not be exported as an outline, and could not be used where no CSS exists — an app icon, a favicon, an email. This is the same mark drawn once, in a 64u square, so every asset is one drawing at a different scale.

One drawing, every size

Favicon, app icon, sidebar avatar, social card: one file, four variants. A squircle plate, a fixed gradient angle, and a glyph that keeps its counters at 16px.

Anatomy

  • plate64u square, radius 14u (22%)
  • glyph26u tall (41% of the plate), stroke 6u
  • airpad 19u on every side — the letter is optically centred, not top-aligned
  • gradient140°, brass.400 → brass.600
  • inkglyph brass.950 — 5.7:1 on the darker end of the ramp
  • spaceclear space 16u (a quarter of the side)

Scale ladder

The deciding size is not the large one — it is 16px beside 14px text, the mark's most common appearance (favicon, app switcher, sidebar header).

Identity

Variants

A variant changes the plate, never the letter. Primary is the default; one colour is a currentColor plate with the glyph knocked out, for inline markup and CSS masks; reverse is an ink plate with a brass glyph, for brass-heavy or light surfaces. The glyph alone is a quiet secondary mark — never the app icon.

Contrast

The glyph is a large solid shape but it is still text, so it holds 4.5:1 against the whole gradient, not only its midpoint.

Identity

Clear space

A quarter of the tile side on every side — the hatched ring below. Nothing enters it: no text, no rule, no edge of a container.

The tile is 64u; the hatched ring is 16u of clear space — a quarter of the side — on every side.

Using it

      
Import order matters, and themes: false is load-bearing: without
        it daisyUI emits its own light and dark themes after ours and they win. The theme file is
        plain custom properties on purpose, so it needs no toolchain — which is also what makes it
        usable from an email template.

      
/* apps/web-ui/app.css — order matters */
@import "tailwindcss";
@plugin "daisyui" { themes: false; }

@import "../../design-system/dist/css/brand.theme.css";
@import "../../design-system/dist/css/brand.tokens.css";

        above is the first consumer — it is the proof that the tokens alone can build an interface.
