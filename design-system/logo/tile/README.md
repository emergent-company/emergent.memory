# The mark — brass tile with a drawn M

The identity is one drawing: a squircle of brass with an **M** in ink. Every asset
in this directory is that drawing at a different scale. There is no second mark
and no alternate letterform.

The drawing lives in `design-system/build.py`; the numbers that define it live in
`design-system/tokens/memory.tokens.json` under `logo.mark.*`. Neither this
README nor an SVG is the source of truth — the token file is, and the generator
re-derives every file from it.

## Why the letter is a path

The shipped monogram (the sidebar `.memory-monogram`, `docs-astro/public/favicon.svg`)
set the M as **live text** in `ui-sans-serif, system-ui`. That has three
consequences a brand asset cannot live with:

1. The letterform changes with the font stack — macOS, Windows, Android and iOS
   each render a different M;
2. it cannot be exported as an outline, so it cannot be an app icon, a favicon or
   an email image;
3. it has no geometry, so nothing about it can be measured, gated or versioned.

The M in this directory is a twelve-point closed path in its own 24u frame. It is
drawn once and used everywhere: as a path in the SVG, as an inline fragment in the
catalogue, and as the value of `logo.mark.glyphPath` in the manifest.

## Geometry

All numbers are in units of **u**. The tile is 64u square, so at a 64px render one
u is one pixel. Nothing is a pixel literal: every value is a ratio, which is what
lets one file serve a 16px favicon and a 1024px icon.

| Token | Value | Rule |
|---|---|---|
| `logo.mark.side` | 64u | The plate. Square. |
| `logo.mark.radius` | 14u | 21.9% of the side. The gate holds radius / side inside **0.20–0.24** — a squircle, not a circle and not a sharp square. |
| `logo.mark.glyphCap` | 26u | Glyph height, 40.6% of the plate. `pad = (side − glyphCap) / 2 = 19u`, so the letter is optically centred on both axes. Gate range **0.36–0.44**. |
| `logo.mark.glyphStroke` | 6u | Stem width in the glyph's own 24u frame (25%). The V band has the same vertical thickness as the stems, so the letter does not thin into a wedge. |
| `logo.mark.gradientAngle` | 140° | CSS degrees, clockwise from "to top". The same angle as the shipped monogram and the app icon. |
| `logo.mark.gradientFrom` | `brass.400` | Light end. The saturated step of the ramp, so the tile has more presence than a brass button without leaving the palette. |
| `logo.mark.gradientTo` | `brass.600` | Dark end. No third colour. |
| `logo.mark.glyphInk` | `brass.950` | The glyph. 9.4:1 on the light end, 5.7:1 on the dark end. |
| `logo.mark.plateInk` | `ink.900` | The reverse plate. |
| `logo.mark.glyphOnInk` | `brass.400` | The reverse glyph, 9.9:1 on the plate. |
| `logo.mark.clearSpace` | 16u | A quarter of the side, on every side. Nothing enters it. |

The glyph's apex stops 1u short of the baseline (inner 14u, outer 23u in its 24u
frame). That is what keeps the counters open at 16px: below about 6px of glyph the
two bowls merge and the letter stops reading, which the gate rejects.

## Files

All generated by `python3 design-system/build.py`. Do not edit them.

| File | What it is | Use |
|---|---|---|
| `memory-tile.svg` | Brass gradient plate, ink glyph. Self-contained. | **The app icon.** Favicon, app icon, avatar, social card, any `<img>`. |
| `memory-tile-mono.svg` | `currentColor` plate, glyph knocked out through a mask. | Inline HTML and CSS masks — anywhere the mark should take the surrounding colour. An `<img>` paints it black. |
| `memory-tile-reverse.svg` | Ink plate, brass glyph. Self-contained. | Brass-heavy or light surfaces where the gradient would blend in. |
| `../glyph/memory-glyph.svg` | The M alone, `currentColor`, 24u square. | A quiet secondary mark — never the app icon. |

The other variants once considered (a circle plate, an outlined tile, a gradient
glyph) are not shipped: each one weakens either the squircle or the "one drawing"
rule.

## Using it

Inline (colours resolve, `currentColor` works):

```html
<!-- paste the contents of memory-tile.svg -->
```

As an image (self-contained variants only):

```html
<img src="/design-system/logo/tile/memory-tile.svg" width="32" height="32" alt="Memory">
```

As a mask (mono, takes the element's colour):

```css
.mark {
  width: 32px; height: 32px;
  background: currentColor;
  -webkit-mask: url(/design-system/logo/tile/memory-tile-mono.svg) center / contain no-repeat;
          mask: url(/design-system/logo/tile/memory-tile-mono.svg) center / contain no-repeat;
}
```

## Never

- Stretch, squash or rotate the tile or the glyph.
- Re-colour the plate to a hue outside the brass ramp, or give the glyph a colour
  other than `glyphInk` / `glyphOnInk`. The gradient and its ink are a pair; the
  gate measures their contrast.
- Outline the glyph, add a stroke, a drop shadow inside the plate, or a second
  letter.
- Place the tile below 16px, on a photograph, or inside a container that eats its
  clear space.
- Set the wordmark in live text. It has to be drawn from the same coordinates or
  it will drift per platform, which is the problem this mark exists to fix.

## Changing it

1. Tune it in the catalogue's **tile workbench** — radius, glyph cap and gradient
   angle, with the same verdicts the gate enforces.
2. Edit `logo.mark.*` in `tokens/memory.tokens.json` with the values it prints.
3. `task brand:build && task brand:check`. If the change is a shape change rather
   than a number, edit `glyph_path()` in `build.py` and keep the twelve-point
   outline.
4. Open `catalog/index.html` and look at the ladder at 16px before committing.
